# 실외 위험구역 대피 MADRL 재설계안

상태: 구현됨(2026-09-23). 구현 내용, 단계별 통과 조건 확인 결과, 이 문서와 다르게 정한 점은 `docs/outdoor_madrl_implementation.md`에 있다. 학습·모델 선택·최종 제로샷 실행은 남아 있다.  
작성일: 2026-09-23  
대상: `SAC_UED4`의 실외 도시 지도, 로봇 1–3대, 고정된 위험구역을 비우고 재진입을 억제하는 과제.

## 1. 목표와 정보 가정

- 하나의 공유 정책이 100×100, 200×200, 400×400 m 지도에서 작동해야 한다. 학습되지 않은 도시 지도와 에피소드마다 무작위로 배치되는 위험구역에 대한 성능은 별도로 검증한다.
- 로봇 팀은 정적 도시 지도와 해당 에피소드의 위험구역 형상을 공유받는다. 이는 군중의 실제 전역 위치를 제공한다는 뜻이 아니다.
- 각 로봇이 군중을 측정하는 기본 범위는 현행 `ROBOT_VISION=10 m` 및 건물 가시선이다. 팀원은 위치·모드·관측 시각과 자신이 측정한 영역·군중을 통신한다. 초기 실험은 지연·손실 없는 통신을 가정하고, 이후 지연·손실을 별도 실험축으로 둔다.
- 어느 로봇도 관측하지 않은 곳은 `군중 0명`이 아니라 **미관측**이다. 통신으로 합친 팀 지도 역시 부분관측이며 시뮬레이터의 정답 지도와 구분한다.
- 학습 중 중앙 critic에만 시뮬레이터의 실제 전역 군중 상태를 줄 수 있다. 실행 actor에게는 줄 수 없다. 이는 중앙 학습·분산 실행(CTDE)의 정보 비대칭이다 [R1]. 학습된 통신 프로토콜 대신 명시적 관측 공유를 먼저 쓰는 것은 프로젝트의 구현 선택이며, TarMAC [R2]의 알고리즘을 구현한다는 주장은 아니다.

## 2. 현재 구현과 수정 범위

현재 `sim/model.py::return_current_image`는 벽(50), 군중(150), 위험구역(200), 로봇(255)을 한 장의 회색조 영상에 덮어 그린다. 신경망의 4채널은 네 의미 채널이 아니라 같은 영상의 최근 4프레임이다. 전역 영상은 50×50으로 최댓값 풀링한다. 400 m에서는 한 칸이 약 8×8 m여서 좁은 통로와 서로 겹친 객체 정보가 손실된다. `return_current_robot_state`의 전체 위험구역 점유율과 시야 밖 추종자 여부도 actor에 전역 동적 정보를 누출할 수 있다.

현재 리플레이는 로봇별 `(3, 4, 25, 25)` 주변 영상과 `(4, 50, 50)` 전역 영상을 현재·다음 상태에 각각 보관한다. `BUFFER_SIZE=1_000_000`을 전부 채울 경우 영상 배열만 약 35 GB(십진 단위)이다. 세부 근거: `config.py`, `sim/model.py`, `learn/ADDS_AS_reinforcement.py`의 설정·관측·`ReplayBuffer`.

## 3. 설정 파일을 세 종류로 분리

| 설정 파일 | 유일한 책임 | 예시 |
| --- | --- | --- |
| `configs/simulation_run.py` | 뷰어·수동 실행 한 번의 선택 | 표시할 지도와 크기, 로봇 수, 불러올 체크포인트, 렌더링·화면 속도 |
| `configs/environment.py` | 시뮬레이터의 물리·측정·공유 관측 계약 | 보행자/로봇 속도와 반경, 위험구역 안전 여유, 시야·가시선·통신, 관측 채널과 해상도 |
| `configs/training.py` | 학습 및 평가 실험의 선택 | SAC/critic, 탐험, 보상, 리플레이, 커리큘럼, **학습·검증·제로샷 지도와 시드**, 로깅·W&B |

뷰어에서 `SIM_REAL_SITE=myeongdong`을 **열어 보는 것**은 실행 설정이다. 명동을 **학습에서 제외하고 최종 제로샷에만 쓰는 것**은 학습 설정이다. 위험구역의 기하와 유효성 규칙은 환경 설정, 학습 중 위험구역 면적·형태의 샘플링 분포와 평가 시드 목록은 학습 설정에 둔다. 관측에 영향을 주는 환경 설정은 체크포인트의 관측 스키마 일부로 취급한다.

진입점에서 세 설정을 한 번 합쳐 불변의 `ResolvedConfig`를 만들고 검증한 뒤 모든 작업자에게 전달한다. 모듈 import 시 프로세스·W&B·파일 생성 같은 부작용을 두지 않는다. 기존 `from config import *` 호출자가 많으므로 초기에는 `config.py`를 호환용 재내보내기로 남기고, 호출부를 명시적 설정 객체로 점진적으로 옮긴다. 최종적으로 동일 설정값의 중복 소유를 없앤다. 시작 시에는 학습/평가 지도 중복, 지원하지 않는 크롭 크기, 로봇 수, 관측/체크포인트 스키마, 비밀키의 설정 파일 포함 여부를 검사한다. 현재 `SAC_UED4/config.py`의 `SIM_REAL_SIZE=150`은 코퍼스 기본 크기 `(100, 200, 400)`과 맞지 않으므로 이 과정에서 검증·수정한다.

## 4. 다채널·다중 해상도 관측

| 가지 | 제안 크기 | 정적 정보 | 동적 정보 |
| --- | --- | --- | --- |
| 주변 | 25×25, 1 m/칸 | 장애물, 위험구역, 지도 밖 마스크 | 자기 시야 내 군중 수, 관측 가능 마스크; 최근 4개 행동 시점 |
| 중간 | 64×64, 2 m/칸, 약 128 m | 통행 가능성, 위험구역 경계, 지역 경로 정보 | 팀원들이 최근 관측한 군중과 관측 시각/나이 |
| 전체 | 64×64, 맵 전체 | 장애물·위험구역 면적 비율, 보행 가능한 위험구역 경계까지의 경로 정보 | 팀 관측의 희소한 요약과 관측된 면적 비율; **정답 군중은 아님** |

주변·중간 가지는 맵 크기와 무관하게 같은 *물리적 거리*를 본다. 전체 64×64의 한 칸은 100/200/400 m에서 각각 약 1.56/3.13/6.25 m이며 지도 크기도 별도 스칼라로 제공한다. 전체 가지는 골목의 정확한 연결을 단독으로 판단하지 않는다. 원래 해상도의 통행 가능 지도에서 계산한 경로 정보와 중간 가지가 이를 보완한다. `escape_distance`는 이미 위험구역 **안에서 안전지대까지**의 경로거리이므로, 위험구역 **밖에서 로봇이 경계로 접근하는** 경로 정보가 필요하면 별도로 정의·계산해야 한다. 지역/전역 지도를 결합하는 방향은 Active Neural SLAM [R3]을 참고하되, 표의 정확한 크기와 채널은 이 프로젝트의 설계값이다.

최댓값 풀링으로 의미를 섞지 않는다. 장애물·위험구역은 각 셀의 점유 비율, 관측 커버리지는 평균 비율, 군중은 관측된 영역의 수/밀도를 목적에 맞게 집계한다. 군중 채널은 관측 마스크와 반드시 함께 전달한다. 정적 지도는 시야 밖까지 알려져 있어도 되지만, 동적 군중은 10 m 및 가시선 범위로 자른다. 기존 `VisibilityAtlas`를 사용하되 로봇 시야 반경을 등록·검증하고, 건물 뒤의 사람이 actor 영상·스칼라 어느 쪽으로도 새지 않게 한다.

각 로봇의 통신 메시지는 `(로봇 위치·모드, 관측 시각, 관측 범위, 측정된 군중)`이다. 겹치는 셀의 관측을 합칠 때 사람을 중복 계수하지 않는다. 일정 시간보다 오래된 군중 위치는 현재 위치인 양 표시하지 않고 만료하거나 별도 `age` 채널로 표시한다. 초기 구현은 최근 4개 행동 시점만 사용하고 무기한 추적 지도는 만들지 않는다. 공통 actor는 자기 주변/중간 입력, 공유 정적 전체 지도, 팀 관측 및 팀원 상태를 받아 행동한다. critic은 공동 관측·공동 행동과 학습 전용 전역 군중 요약을 받는다.

제안 설정의 기본값은 `ACTOR_GLOBAL_CROWD_TRUTH=False`, `TEAM_SHARE_OBSERVATIONS=True`, `CRITIC_PRIVILEGED_CROWD=True`이다. 첫째 값을 켜는 경우는 현실 기본값이 아닌 완전정보 상한 실험이며 별도 체크포인트·실험 태그를 사용한다. 통신이 있어도 보지 못한 사람의 위치를 알 수 없으므로 400 m에서의 예방 성능은 순찰·배치 전략에 의존한다는 한계를 명시한다.

## 5. MADRL, 행동, 보상

1. **기존 형식과 호환되는 우선 수정:** 중앙 critic의 로봇별 출력은 마스크를 적용한 **팀 평균 Q**로 평가한다. critic 손실과 actor 손실, 두 critic의 `min` 적용 순서를 같은 팀 Q 정의에 맞춘다. 다른 로봇 행동을 리플레이 값으로 고정하는 단일 로봇 반사실적 actor 갱신은 유지한다. 남아 있는 2차원 ε 탐험 분기를 7차원 공통 행동 생성기로 교체하고, 저장 모델의 일반 실행에서도 모든 로봇에 정책을 적용한다.
2. **이동 명령은 당분간 유지:** 현재 `[-2,2]` 명령이 최고속도에서 포화되는 것은 중복 표현이지만 100 m 성능 실패의 증거는 아니다. 명령 크기·실제 속도·모드 전환율을 기록하고, 변경 필요성은 독립된 비교 실험에서 판단한다. `off/guide/direct`의 행동 의미와 물리 상한은 그대로 둔다.
3. **새 과제 보상:** 매 시뮬레이션 스텝의 위험구역 내 사람 수(사람-시간), 안전지대까지 남은 보행 경로거리, 구역 밖→안 진입 사건, **모든 로봇**의 충돌을 기본항으로 한다. 규모가 다른 지도에서도 가중치 의미가 비슷하도록 에피소드 시작 시 정한 기준 인구·거리 척도로 정규화한다. 유입에 따라 증가하는 누적 `total_agents`를 분모로 사용하지 않는다. 정상적인 맵 유출은 재진입으로 세지 않으며, 원래 통행에 따른 유출 자체를 로봇 보상으로 곧바로 해석하지 않는다.
4. **시간 집계:** 행동을 `ACTION_SCALE=4` 시뮬레이션 스텝 유지했다면 네 스텝의 보상을 적산한다. 리플레이에 실제 유지 길이 `k`를 넣고 부트스트랩은 해당 길이에 맞는 할인율을 사용한다. 첫 행동 구간과 조기 종료 구간도 누락하지 않는다.

관측·보상·행동 형식이 바뀌는 실험에는 각각 `observation_schema_version`, `reward_version`, `action_schema_version`을 붙인다. 옛 리플레이와 커리큘럼 성공 이력을 새 의미로 조용히 읽지 않는다. 기존 가중치 전이는 명시적인 실험으로만 허용하고 기본값은 새 학습이다.

## 6. 리플레이와 메모리 예산

현재 영상 저장량의 계산은 전이당 `2 × (3×4×25×25 + 4×50×50) = 35,000` 바이트, 100만 전이에 약 35 GB다. 다채널·다중 해상도 영상을 현재/다음 상태와 시간 스택으로 모두 복사하면 이보다 훨씬 커진다.

새 저장 단위는 다음과 같다.

1. 정적 건물·위험구역·경로 필드는 **지도 기하와 위험구역 배치별**로 한 번만 저장한다. 같은 OSM 도시라도 위험구역 시드가 다르면 다른 키다. 리플레이가 참조하는 정적 자료는 RAM 캐시에서 빠져도 디스크 등에 남아 재구성 가능해야 한다.
2. 동적 원본은 로봇별 측정 프레임을 시점당 한 번 저장한다. 예시로 25×25 `uint8` 군중 수는 625 B, 비트 압축 관측 마스크는 약 79 B이므로 로봇당 약 704 B, 3대면 약 2.1 KB다. 현재·다음 상태와 4프레임은 안전한 시점 인덱스로 재구성하며 에피소드 경계를 넘지 않는다.
3. 중간·전체의 **팀 관측**은 측정 원본과 로봇 위치에서 재구성한다. 학습 전용 critic의 64×64 `uint8` 전역 군중 요약을 저장한다면 시점당 약 4 KB가 추가된다. 이는 actor의 입력으로 연결하지 않는다.
4. 위 예시의 원시 동적 영상 합계는 시점당 약 6.2 KB, 10만 시점에서 약 620 MB다. 로봇 상태·행동·인덱스·정적 캐시·파이썬 객체·학습 배치·GPU 메모리는 **별도**다. 실제 최대 메모리와 재구성 시간을 측정한 후 `BUFFER_SIZE`를 결정한다. 10만은 계측 출발점이지 확정 하이퍼파라미터가 아니다.

## 7. 학습 지도, 크기별 검증, 최종 제로샷

학습 지도·검증 지도·최종 제로샷 지도는 모두 `configs/training.py`에서 선언한다. 지도명뿐 아니라 지리적 장소, 크롭의 공간 중첩, 생성 시드, 위험구역 시드를 검사해 학습/최종 평가 누출을 막는다. 100/200/400 m 생성 지도에서 학습·검증을 준비하되, 400 m 목표 밀도에서의 계산 비용을 먼저 계측한다. 일부 크기를 낮은 밀도로만 실행했다면 크기 일반화와 밀도 일반화를 분리 보고한다. 미지 레벨의 별도 평가가 필요한 이유는 Procgen [R4]을 참고한다.

최종 실외 OSM 제로샷의 **사전등록 후보**는 기존 제로샷 네 지역에 없는 `myeongdong` 400×400 m **지도 한 곳**이다. 최종 지도를 모델 선택에 사용하지 않는다. 모델을 확정한 뒤 미리 고정한 여러 위험구역 시드(위치·면적·형태)와 군중 시드에서 로봇 1/2/3대 및 동일 조건의 `off_zero_command` 대조군을 짝지어 평가한다. 평가 전 위험구역의 보행 가능 면적·안전지대 접근성·유효 밀도를 검사하고 탈락 기준과 시드를 기록한다. 현재 생성 학습 지도는 위험구역이 무작위지만 OSM 제로샷은 지역당 고정 시드 한 배치만 사용하므로 반복 시드 평가로 바꾼다. 현재 OSM의 `street` 위험구역은 거리망 기반으로 배치되지 않고 직사각형으로 대체되므로 별도 구현·검증 전까지 실제 거리 정렬 위험구역이라고 보고하지 않는다.

저장된 `myeongdong` 400 m OSM 레벨은 800명, 실제 밀도 약 0.02027명/m²다. 현 목표 0.04–0.05명/m²보다 낮으므로 설정의 인원 상한만 올렸다고 목표 밀도 평가가 되지 않는다. 레벨 인원을 다시 산정하고 실행시간을 측정해야 한다. 불가능하면 낮은 밀도 결과로 명시한다. 최종 지도 선택과 위험구역 시드는 **정책 성능을 보기 전에** 확정한다. 주기적 평가는 별도의 생성 지도 홀드아웃으로 수행하고, 최종 OSM 지도를 매 5,000 에피소드마다 반복 조회해 모델을 고르는 현 경로는 분리한다.

주 지표는 위험구역 사람-스텝, 재진입 사건, 비움 유지 성공률·시간과 OFF 대비 차이이다. 유입·유출 및 유출 사유, 실제 밀도, 로봇 수, 지도 크기, 추론 시간도 함께 남긴다. 유출 총량만 로봇 효과로 주장하지 않으며 실패한 에피소드를 시간 평균에서 숨기지 않는다. 기존 평가 지표의 의미는 `docs/zero_shot_evaluation.md`를 참고한다.

## 8. TXT·TensorBoard·W&B의 단일 로깅 경로

현재는 에피소드별 TXT 파일을 여러 감시 스레드가 다시 읽어 TensorBoard에 쓰는 경로가 있다. 새 구조에서는 **주 학습 프로세스의 하나의 구조화된 지표 이벤트**를 로컬 JSONL(원본), 기존 TXT(호환 출력), TensorBoard, W&B로 보낸다. 작업자는 지표 메시지만 전달하고 W&B run을 생성하지 않는다. 직접 `run.log()`를 사용하므로 `sync_tensorboard=True`를 동시에 켜 중복 기록하지 않는다. W&B는 한 번에 묶은 지표를 적절한 주기로 기록하고 `global_update`·`global_episode`를 분리된 차트 축으로 둔다 [W1, W2].

학습 설정에는 `wandb.project`, `entity`, `mode=(online|offline|disabled)`, 기록 주기, 체크포인트 업로드 정책을 둔다. 일반 학습에서 `online`을 선택하면 wandb.ai에 동기화하고, 네트워크가 없는 환경에서는 명시적 `offline` 모드로 로컬 저장 후 동기화한다 [W3]. 인증 정보는 설정·체크포인트·로그에 저장하지 않는다. W&B 오류가 학습 결과를 잃게 하지 않도록 로컬 로그는 계속 남기고 실패를 명확하게 보고한다. 거대한 리플레이나 모든 주기적 체크포인트를 기본 업로드하지 않고 선별된 모델만 선택적으로 artifact로 기록한다.

모든 기록에 세 설정의 **해결된 값**, 지도 분할·위험구역 시드, 실제 밀도, 관측/행동/보상 스키마 버전, 실행 코드 버전, 실험 ID를 넣는다. 감시 프로세스 재시작 시 W&B run ID와 학습 카운터가 연속일 때만 기존 run을 이어 쓰고, 카운터가 되돌아갔다면 새 run으로 분리해 같은 실험 그룹으로 묶는다 [W4]. TensorBoard·TXT·JSONL·W&B의 같은 이벤트 값과 축이 일치하는지 테스트한다.

## 9. 구현 순서와 통과 조건

1. **기준선·설정·로거:** 현재 지표와 체크포인트 형식 기록, 설정 3분할 및 시작 시 검증, 동일 이벤트의 TXT/JSONL·TensorBoard·W&B 기록. W&B `disabled/offline` 테스트를 먼저 실행한다.
2. **기존 형식의 학습 오류:** 팀 Q 목적함수, 7차원 ε 탐험, 모든 로봇의 일반 추론. 1/2/3대 회귀 테스트와 기존 모델·새 코드의 비교 실행을 남긴다.
3. **보상·시간 의미:** 사람-시간/경로거리/재진입/전 로봇 충돌 및 4스텝 집계. 유입·유출이 있는 작은 결정적 시나리오와 크기별 보상 규모 테스트를 통과한다.
4. **부분관측·통신·다중 해상도:** 시야 밖 사람을 이동시켜도 actor 입력은 변하지 않고 critic 입력만 변해야 한다. 팀원이 새로 관측하면 공유 입력이 바뀌어야 하며, 겹친 관측은 중복 계수되지 않아야 한다. 학습·뷰어·제로샷이 같은 관측 생성기를 사용한다.
5. **리플레이·성능:** 정적 자료 재구성, 4프레임/에피소드 경계, 스키마 불일치 거부, 100/200/400 m의 RAM·GPU 피크와 처리량 측정. 목표 밀도 400 m가 비용상 가능한지 결정한다.
6. **평가:** 생성 지도 크기별 검증으로 모델을 선택한 후 사전등록한 단일 OSM 지도에서 위험구역 시드별 최종 제로샷을 실시한다. 근거 문서와 실험 설정·원시 지표를 함께 보존한다.
